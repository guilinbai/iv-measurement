## 0. 先建立整体印象（30 秒）

Arduino 程序**只有两个必须的函数**：

| 函数 | 什么时候跑 | 跑几次 |
|---|---|---|
| `setup()` | 上电/复位后 | **只跑一次** |
| `loop()` | setup 之后 | **反复跑，直到断电** |

我们这个程序的完整调用关系：

```
        ┌──────────────────────────┐
        │  setup()                 │  上电一次：
        │  · 设 10 个引脚为输出     │  ① 串口初始化
        │  · 进安全态              │  ② 设引脚方向
        │  · 选电流模式            │  ③ 进安全态 + 选模式
        └───────────┬──────────────┘  ④ 打印横幅
                    ▼
        ┌──────────────────────────┐
   ┌───▶│  loop()                  │  反复跑：
   │    │  handleSerial()  ← 先看有没有命令
   │    │  if (autoRun) 才扫描 4 路
   │    └───────────┬──────────────┘
   │                ▼
   │    ┌──────────────────────────┐
   │    │ handleSerial()           │  读串口命令：a / i1~i4 / v1~v4 / c / u / s
   │    └───────────┬──────────────┘
   │                ▼
   │    ┌──────────────────────────┐
   └────│ measureIsc() / measureVoc│  核心时序（5 步）
        │ 或 allSafe() / switchMode│
        └──────────────────────────┘
```

**一句话总结这个程序在干什么**：它是一台"自动拨开关的机器"——按固定时序把 4 个被测器件轮流接到万用表上，并留出时间窗口让上位机读数。

## 1. 第 1~27 行：开头那段长注释

```cpp
/* ============================================================================
 *  4 路 IV 测量 —— Arduino Nano 控制固件  v1.0
 *  接线见《5-面包板排线教程.md》：
 *    D2  = 通道1 选通（同时驱动 光耦-1、光耦-2）
 *    ...
 * ==========================================================================*/
```

**这不是废话，是故意写的"说明书"**。理由很实在：

- 半年后你回来看这个文件，第一句话就能想起"哦，D2 是通道1 选通"；
- Arduino 程序**必须和接线一一对应**——接线错了，代码再对也没用；
- 把"电平约定"写在最上面尤其重要：

```
电平约定：光耦 LED 高电平 = 导通 = 开关闭合
  选通 HIGH = 器件接上万用表；短接 HIGH = 器件两端被短接
  安全态 = 选通全 LOW + 短接全 HIGH
```

> 💡 **这就是"读代码先读注释"的原因**：注释告诉你"意图"，代码只告诉你"动作"。

## 2. 第 29~32 行：引脚表（数组的用法）

```cpp
const uint8_t PIN_SEL[4]   = {2, 4, 6, 8};
const uint8_t PIN_SHORT[4] = {3, 5, 7, 9};
const uint8_t PIN_MODE_I   = 10;
const uint8_t PIN_MODE_V   = 11;
```

### 逐词拆解第一行

| 写法 | 含义 | 为什么这么写 |
|---|---|---|
| `uint8_t` | 一种**数据类型**：0~255 的整数（8 位无符号） | 引脚号最大 19，用 `int`（2 字节）浪费 RAM；Nano 只有 2 KB RAM，能省就省 |
| `PIN_SEL` | 变量名（自己起的） | SEL = select（选通） |
| `[4]` | 这是**4 个数的数组**，下标是 0/1/2/3 | 因为有 4 个通道 |
| `= {2, 4, 6, 8}` | 初始化：第 0 个是 2，第 1 个是 4…… | 对应 D2/D4/D6/D8 |
| `const` | **常量**——之后不许改它 | 防止手滑改错；编译器还能顺便优化 |

所以：

```cpp
PIN_SEL[0] = 2    // 通道1（下标 0）的选通用 D2
PIN_SEL[1] = 4    // 通道2 的选通用 D4
PIN_SEL[2] = 6
PIN_SEL[3] = 8
```

对照 `PIN_SHORT[4] = {3, 5, 7, 9}`，会发现一个**规律**：

```
通道下标    0     1     2     3
选通脚      2     4     6     8     ← 偶数
短接脚      3     5     7     9     ← 奇数
```

**记住这个"奇偶配对"**，看接线和排错时非常有用。

### 为什么做成数组，而不是写 8 个变量？

对照一下两种写法：

```cpp
// 写法 A：8 个独立变量（不推荐）
const uint8_t SEL1=2, SEL2=4, SEL3=6, SEL4=8;
const uint8_t SH1=3, SH2=5, SH3=7, SH4=9;

// 写法 B：数组（本程序用的）
const uint8_t PIN_SEL[4]   = {2, 4, 6, 8};
const uint8_t PIN_SHORT[4] = {3, 5, 7, 9};
```

写法 B 的好处：**可以用 for 循环一次处理 4 个通道**：

```cpp
for (uint8_t i = 0; i < 4; i++) {
  digitalWrite(PIN_SEL[i], LOW);      // 一句话操作 4 个引脚
}
```

如果将来改成 8 路，写法 B 只要把 `[4]` 改成 `[8]`、数字补上；写法 A 要改十几处。

### 第 31~32 行：不用数组的情况

```cpp
const uint8_t PIN_MODE_I   = 10;   // 模式耦合器·电流 → D10
const uint8_t PIN_MODE_V   = 11;   // 模式耦合器·电压 → D11
```

只有两个、而且不参与循环 → 直接一个变量一个值，更直观。

## 3. 第 34~39 行：时间参数（你会最常改的地方）

```cpp
// -------- 时间参数（毫秒）--------
uint16_t T_OPEN     = 30;
uint16_t T_SETTLE   = 80;
uint16_t T_DWELL    = 60;
uint16_t T_OFF      = 20;
uint16_t T_INTERVAL = 1000;
```

### 先看类型：`uint16_t`

| 类型 | 范围 | 用在这里的理由 |
|---|---|---|
| `uint8_t` | 0 ~ 255 | 最多 0.25 秒，不够 |
| **`uint16_t`** | **0 ~ 65535** | 最大约 **65 秒**，够用 |
| `unsigned long` | 0 ~ 42 亿 | 用不着，浪费 RAM |

### 再看每个参数对应时序的哪一段

```
        ┌── T_OPEN ──┐┌─ T_SETTLE ─┐┌─ T_DWELL ─┐┌─ T_OFF ─┐
        │            ││            ││           ││         │
短接脚 ─┘            └────────────────────────────────────────┘   (HIGH=器件被短接)
                         ┌────────────────────┐
选通脚 ──────────────────┘                    └────────────────     (HIGH=器件接表)

     ①断短接        ②合选通              ③读数窗口      ④断选通   ⑤合短接
```

| 参数 | 值 | 作用 | 什么时候要调 |
|---|---|---|---|
| `T_OPEN` | 30 ms | 断开短接后，等器件**升到开路电压** | 器件电容大（如电化学）→ 加大 |
| `T_SETTLE` | 80 ms | 合上选通后，等**放电瞬态衰减、表稳定** | 表读数还在跳 → 加大 |
| `T_DWELL` | 60 ms | **读数窗口**：上位机在这段时间读表 | 表响应慢 / NPLC 设得高 → 加大 |
| `T_OFF` | 20 ms | 断选通和合短接之间的空档 | 保证"两个开关不同时导通" |
| `T_INTERVAL` | 1000 ms | 扫完 4 路后等多久开始下一轮 | = 你的采样间隔 |

> ⚠️ **注意这 5 个变量没有 `const`**——这是故意的：将来可以用串口命令在运行时改它们（比如"把稳定时间调到 200 ms"）。`const` 了就改不了。

## 4. 第 41~42 行：两个状态变量

```cpp
bool autoRun     = false;   // 是否在自动循环（默认关）
bool currentMode = true;    // true=电流模式，false=电压模式（默认电流）
```

- `bool` 类型只有两个值：`true` / `false`；
- **为什么需要它们？** 因为 `loop()` 每一轮都要根据这两个状态决定"做什么"：

```
if (autoRun)  → 才去扫描 4 路；否则就只是等命令
if (currentMode) → 测 Isc；否则测 Voc
```

> 💡 这两个变量相当于机器的"开关状态记忆"。`autoRun` 由串口命令 `a` 翻转，`currentMode` 由 `c`/`u` 切换。

## 5. 第 44~49 行：`allSafe()` —— 安全态

```cpp
void allSafe() {
  for (uint8_t i = 0; i < 4; i++) {
    digitalWrite(PIN_SEL[i],   LOW);    // 选通：全部断开
    digitalWrite(PIN_SHORT[i], HIGH);   // 短接：全部闭合
  }
}
```

### 逐行读

```cpp
void allSafe() {
```
定义一个**没有返回值**（`void`）、**不需要参数**（空括号）的函数，名字叫 `allSafe`。

```cpp
for (uint8_t i = 0; i < 4; i++) {
```
**for 循环**，读法是：

| 部分 | 含义 |
|---|---|
| `uint8_t i = 0` | 一开始 i 等于 0 |
| `i < 4` | 只要 i 小于 4 就继续循环 |
| `i++` | 每轮结束 i 加 1 |

所以 i 会取 **0、1、2、3**（正好是 4 个通道的下标）。

```cpp
digitalWrite(PIN_SEL[i],   LOW);
```
把第 i 个通道的选通脚拉低 → **光耦断开 → 器件离表**。

```cpp
digitalWrite(PIN_SHORT[i], HIGH);
```
把第 i 个通道的短接脚拉高 → **光耦闭合 → 器件两端被短接**。

### 为什么需要"安全态"？

安全态解决了两个问题：

| 器件状态 | 好处 |
|---|---|
| **被短接**（短接脚 HIGH） | 器件工作在 0 V，不会被长期开路"晾着"；也是本项目的串扰抑制措施 |
| **离表**（选通脚 LOW） | 不占用万用表，不会误接 |

所以：

- **上电第一件事**就是 `allSafe()`；
- 串口敲 `s` 也会立刻回到这里；
- 自动循环停下来时（再敲一次 `a`）也回到这里。

## 6. 第 51~64 行：`switchMode()` —— 带互锁的模式切换

```cpp
void switchMode(bool toCurrent) {
  if (toCurrent == currentMode) return;
  if (toCurrent) {
    digitalWrite(PIN_MODE_V, LOW);
    delay(10);
    digitalWrite(PIN_MODE_I, HIGH);
  } else {
    digitalWrite(PIN_MODE_I, LOW);
    delay(10);
    digitalWrite(PIN_MODE_V, HIGH);
  }
  currentMode = toCurrent;
  delay(60);
}
```

### 逐行读

```cpp
void switchMode(bool toCurrent) {
```
有**一个参数** `toCurrent`：想切到电流模式就传 `true`，切到电压模式传 `false`。

```cpp
if (toCurrent == currentMode) return;
```
**如果已经在这个模式了，就立刻返回**（什么都不做）。
`return` 在 `void` 函数里表示"提前结束函数"。好处：避免不必要的继电器动作，也少等 70 ms。

```cpp
if (toCurrent) {
  digitalWrite(PIN_MODE_V, LOW);   // ① 先断电压端口
  delay(10);                       // ② 空等 10 ms ← 关键！
  digitalWrite(PIN_MODE_I, HIGH);  // ③ 再合电流端口
}
```

**`delay(10)` 这一行是整个函数最重要的地方**：

> 万用表的电流端口内阻只有约 1 Ω，电压端口是 10 GΩ 级。
> 如果两个耦合器**同时导通**，1 Ω 会把 10 GΩ 旁路掉 → **电压读数立刻失效**。
> 这 10 ms 空档保证"先断一个，再合另一个"，物理上不可能同时导通。

切到电压模式的那段（`else` 分支）同理，只是顺序反过来：**先断电流，再合电压**。

```cpp
currentMode = toCurrent;   // 记住新模式，下次比较用
delay(60);                 // 等万用表内部继电器 + 量程稳定
```

## 7. 第 66~90 行：`measureIsc()` —— 全文最重要的 11 行

```cpp
void measureIsc(uint8_t ch) {
  digitalWrite(PIN_SHORT[ch], LOW);   // ① 先断短接
  delay(T_OPEN);
  digitalWrite(PIN_SEL[ch], HIGH);    // ② 再合选通
  delay(T_SETTLE);
  delay(T_DWELL);                     // ③ 读数窗口
  digitalWrite(PIN_SEL[ch], LOW);     // ④ 先断选通
  delay(T_OFF);
  digitalWrite(PIN_SHORT[ch], HIGH);  // ⑤ 再合短接
  delay(10);
}
```

### 对照时序图读

```
 D3(短接)  ────┐                                    ┌──────────
               └────────────────────────────────────┘
 D2(选通)  ─────────┐                        ┌───────────────
                    └────────────────────────┘
              ①    ②                    ③    ④        ⑤
              断    合                    读    断        合
              短接  选通                  数    选通      短接
```

### 为什么是这个顺序（这是本项目的核心设计）

| 步骤 | 动作 | 物理意义 |
|---|---|---|
| ① | **先断短接** | 器件脱离 0 V，升到开路电压 Voc |
| ② | **再合选通** | 器件接到电流表。此刻短接已经断开 → **表里流过的是器件完整电流，没有被短接开关分流** |
| ③ | 保持 | 给上位机读表的时间窗口 |
| ④ | **先断选通** | 器件离表（先离开，防止下一步短路时表还在回路里） |
| ⑤ | **再合短接** | 回到间隙态 |

> 如果顺序反过来（先合选通、再断短接），合选的瞬间短接开关（约 0.35 Ω）会和测量通路**并联分流**，表读到的就不是完整电流了。

### 一个有意思的观察

`measureVoc()`（第 80~90 行）和它**代码一模一样**：

```cpp
// 测 Voc：同样的 break-before-make 顺序
void measureVoc(uint8_t ch) {
  ...完全相同...
}
```

为什么？因为**电气动作确实相同**——都是"先断短接、再器件接表、读完离开"。区别只在于：

- 电流模式时，万用表处于**电流档**（内部近短路）；
- 电压模式时，万用表处于**电压档**（内部高阻）。

**表处于哪个档位由 `switchMode()` 决定，不由这两个函数决定。**

> 那为什么不合并成一个函数？因为将来很可能需要**分别调参数**——比如 Voc 的稳定时间可能需要更长（高阻源充电慢）。留两个函数，改起来互不影响。

## 8. 第 92~114 行：`handleSerial()` —— 串口命令解析

```cpp
void handleSerial() {
  if (!Serial.available()) return;
  String cmd = Serial.readStringUntil('\n');
  cmd.trim();
  if (cmd.length() == 0) return;
  char c = cmd.charAt(0);
```

| 行 | 含义 |
|---|---|
| `if (!Serial.available()) return;` | **没收到数据就立刻返回**。`!` 是逻辑取反；`available()` 返回"缓冲区里有多少字节"。**这一行让函数不阻塞**——没命令时不浪费一毫秒 |
| `String cmd = Serial.readStringUntil('\n');` | 一直读到换行为止，整行存进 `cmd`（`String` 是 Arduino 的字符串类型） |
| `cmd.trim();` | 去掉首尾的空格、回车、换行 |
| `if (cmd.length() == 0) return;` | 空行就忽略 |
| `char c = cmd.charAt(0);` | 取第 0 个字符，用来判断是什么命令（`char` = 单个字符） |

接着是**命令分发**（一长串 `if / else if`）：

```cpp
  if (c == 'a') {
    autoRun = !autoRun;                                    // 取反：开↔关
    if (!autoRun) allSafe();                               // 停下来了就回安全态
    Serial.println(autoRun ? F(">> auto run START") : F(">> auto run STOP (safe state)"));
  }
```

- `autoRun = !autoRun;` —— **`!` 取反**：原来是 `true` 就变 `false`，反之亦然。这样一条命令就能当开关用。
- `autoRun ? A : B` —— **三元运算符**：`条件 ? 成立时 : 不成立时`。等价于：

```cpp
if (autoRun) Serial.println(F(">> auto run START"));
else         Serial.println(F(">> auto run STOP (safe state)"));
```

- `F("...")` —— 一个很有用的宏：把字符串常量放到 **Flash**（程序存储区）而不是 RAM。Nano 的 RAM 只有 2 KB，字符串多了会被撑爆。**所有固定文本都该用 `F()` 包起来**。

```cpp
  else if (c == 'c') { switchMode(true);  Serial.println(F(">> CURRENT mode")); }
  else if (c == 'u') { switchMode(false); Serial.println(F(">> VOLTAGE mode")); }
  else if (c == 's') { autoRun = false; allSafe(); Serial.println(F(">> SAFE state")); }
```
三条一行命令，直接调用对应的函数。

```cpp
  else if ((c == 'i' || c == 'v') && cmd.length() >= 2) {
    uint8_t ch = cmd.charAt(1) - '1';
    if (ch > 3) { Serial.println(F("!! channel must be 1~4")); return; }
```

这三行有两个**关键技巧**：

**① 字符转数字：`cmd.charAt(1) - '1'`**

字符 `'1'` 在计算机里存的不是数字 1，而是 ASCII 码 **49**。所以：

```cpp
'1' - '1' = 0     // 通道1 → 下标 0
'2' - '1' = 1     // 通道2 → 下标 1
'4' - '1' = 3     // 通道4 → 下标 3
```

一行就完成了"输入 'i3' → 操作通道下标 2"的转换。

**② 越界检查：`if (ch > 3)`**

如果用户输入 `i9`，`'9'-'1' = 8`，直接拿去当数组下标会**越界访问**（读到数组外面的内存，行为不可预测）。所以必须先检查、报错、返回。

```cpp
    if (c == 'i') { switchMode(true);  measureIsc(ch); Serial.println(F(">> Isc done")); }
    else          { switchMode(false); measureVoc(ch); Serial.println(F(">> Voc done")); }
  }
  else Serial.println(F("!! commands: a / i1..i4 / v1..v4 / c / u / s"));
```

- 测 Isc 前**自动切到电流模式**（很贴心的设计，你不用手动先敲 `c`）；
- 最后的 `else` 兜底：输错了给出命令列表。

## 9. 第 116~132 行：`setup()` —— 上电只跑一次

```cpp
void setup() {
  Serial.begin(115200);
  for (uint8_t i = 0; i < 4; i++) {
    pinMode(PIN_SEL[i],   OUTPUT);
    pinMode(PIN_SHORT[i], OUTPUT);
  }
  pinMode(PIN_MODE_I, OUTPUT);
  pinMode(PIN_MODE_V, OUTPUT);

  allSafe();
  switchMode(true);
  delay(500);

  Serial.println(F("=== 4CH IV controller v1.0 ==="));
  ...
}
```

| 行 | 作用 | 注意点 |
|---|---|---|
| `Serial.begin(115200);` | 打开串口，波特率 115200 | **必须和串口监视器右下角选的波特率一致**，否则是乱码 |
| `pinMode(..., OUTPUT);` ×10 | **把 10 个引脚设成输出** | ★ 就是上次你踩的坑！不设 OUTPUT 的话引脚是输入高阻，`digitalWrite` 只能给 0.1 mA，带不动光耦 |
| `allSafe();` | 先保证安全状态 | **上电第一件事** |
| `switchMode(true);` | 默认选电流模式 | 传 `true` = 电流 |
| `delay(500);` | 等一切稳定 | 给光耦和表一点时间 |
| `Serial.println(...)` | 打印横幅 | 你在监视器里看到的那三行 |

**上电后的顺序很讲究**：先设引脚（否则引脚状态不确定）→ 再进安全态 → 再选模式。**绝不能先选模式再设引脚**。

## 10. 第 134~145 行：`loop()` —— 主循环

```cpp
void loop() {
  handleSerial();                        // ① 每轮先看有没有命令
  if (autoRun) {                         // ② 只有开了自动才扫描
    for (uint8_t ch = 0; ch < 4; ch++) {
      if (currentMode) measureIsc(ch); else measureVoc(ch);
      Serial.print(F("CH")); Serial.print(ch + 1);
      Serial.println(currentMode ? F(" Isc done") : F(" Voc done"));
      handleSerial();                    // ③ 每路之间也检查命令
    }
    delay(T_INTERVAL);                   // ④ 整轮间隔
  }
}
```

逐个说：

**① `handleSerial()`**
不扫描的时候，这个函数会**瞬间返回**（因为 `Serial.available()` 是 0），所以 loop 转得飞快，随时响应命令。

**② `if (autoRun)`**
只有敲过 `a` 之后才会进这个分支。没开自动时，loop 就只是"不停查命令"，几乎不耗资源。

**③ `Serial.print(ch + 1)`**
注意 `ch + 1`：`ch` 是下标（0~3），打印时改成人类习惯的 1~4。

**④ 第 141 行的 `handleSerial()`（在 for 里面）**
这是刻意加的：一轮 4 路的扫描要花约 1 秒（4 × 约 200 ms + 间隔），**如果中途想急停（敲 `s`），必须每路之间也检查一次命令**。否则你得等整轮跑完。

**⑤ `delay(T_INTERVAL)`**
整轮之间的等待。**注意这是一个"阻塞"延时**：这 1 秒里程序卡在 delay 里，**不响应任何命令**。这是简单实现的代价——将来如果要更灵敏，可以改成用 `millis()` 计时的非阻塞写法。

### 练习 5：扩到 8 路（重要提示）

## 14. 一页速记

```
setup()  上电跑一次：串口 → 设 10 个引脚为 OUTPUT → 安全态 → 选电流模式 → 打印横幅
loop()   反复跑：查命令 → (若 autoRun) 4 路轮流测量 → 等 1 秒

核心函数：
  allSafe()      选通全 LOW + 短接全 HIGH     （器件被短接、离表）
  switchMode(x)  先断一个耦合器 → 等 10ms → 再合另一个（互锁！）
  measureIsc(ch) 断短接 → 合选通 → 等 → 读数窗口 → 断选通 → 合短接
  handleSerial() 解析 a / i1~i4 / v1~v4 / c / u / s

三条铁律：
  1. pinMode(OUTPUT) 必须在 digitalWrite 之前
  2. 选通与短接、电流与电压耦合器，都绝不同时导通
  3. 上传前先关串口监视器
```
