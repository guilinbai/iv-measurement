### 两台万用表（USB）

| 用途 | VISA 地址 | 序列号 | 固件 | 当前功能 |
|---|---|---|---|---|
| **测电压** | `USB0::0x05E6::0x6500::04587682::INSTR` | 04587682 | 1.7.12b | `VOLT:DC` |
| **测电流** | `USB0::0x05E6::0x6500::04468141::INSTR` | 04468141 | 1.0.04b | `CURR:DC` |

两台都在 **NPLC=1、自动调零开、电压量程 0.1 V、电流量程 10 µA** —— 正好适合小信号器件。

### 关键实测数据（决定时序参数）

| 指标 | 实测值 | 影响 |
|---|---|---|
| `:READ?` 耗时 | **约 25 ms**（两台一致） | 固件 `T_WINDOW=50 ms` 有 2 倍余量 |
| 电压档本底噪声 | ±0.1 mV 波动 | 远优于 mV 级信号 ✓ |
| **电流档本底** | **±20~50 pA** | 比 10 µA 信号低 5 个数量级 ✓ 系统很干净 |
| 一轮 8 次测量 | **实测 1.59 s**（设计预算 1.56 s，误差 2%） | **采样间隔 2 s 可行**（余量 0.41 s） |

### 串口

| 端口 | 设备 | 说明 |
|---|---|---|
| **COM9** | USB-SERIAL CH340 | **Arduino（开关阵列）** ✓ |
| COM11 | USB-SERIAL CH340 | 另一个 CH340 设备（不是 Arduino） |
| COM5 / COM6 | 蓝牙串口 | **不要探测**（Windows 打开会卡住，脚本已自动跳过） |
| COM1 | 主板串口 | 同上 |

> ⚠️ **CH340 没有序列号**，而且 USB 重新插拔后端口号会变（实测已从 `COM7/COM9` 变成 `COM9/COM11`）。
> 所以 `config.yaml` 里 `arduino.port` **建议留空**，由程序**自动探测**（发 PING，谁回应谁是 Arduino）。

## 五、config.yaml 怎么改

| 想要什么 | 改哪里 |
|---|---|
| 换数据存放位置 | `storage.dir` |
| 改采样间隔 | `acquisition.interval_s`（**最小 1.4 s**，否则一轮跑不完） |
| 关闭"边测边写 CSV" | `storage.write_csv_realtime: false`（不推荐，会失去断电保护） |
| 手动指定 Arduino 端口 | `devices.arduino.port: "COM9"`（留空则自动探测） |
| 调整读数精度/速度 | `devices.dmm_*.nplc`（小信号建议保持 1） |

### ⚠️ 间隔保护（程序会提示）

| 采样间隔 | 一轮 1.56 s 之后的余量 |
|---|---|
| 2.0 s（当前） | 0.44 s ✓ 够 |
| 1.5 s | -0.06 s ✗ 跑不完 |
| **最小建议** | **1.87 s**（= 1.56 × 1.2） |

程序会在间隔过小时红色警告，并可自动延长。

## 六、常见问题

| 现象 | 原因 / 解决 |
|---|---|
| `[X] 打开 VISA 失败` | NI-VISA 没装，或万用表被其它软件占用（KickStart 等） |
| 只找到 1 台表 | 检查另一台 USB 是否插好；两台表的 USB 线别插在同一个 Hub 上尝试换口 |
| 串口无回应 | ① Arduino 被 IDE 的串口监视器占用 → 关掉；② 数据线是"只能充电"的线；③ 板子没插好 |
| 脚本输出中文乱码 | 用 **Windows Terminal** 或 **VS Code** 的终端运行；或在 cmd 里先执行 `chcp 65001` |
| 探测串口卡住很久 | 已修复：脚本现在**只探测 USB 串口芯片**，自动跳过蓝牙/主板串口 |
| 上传固件报"拒绝访问" | 串口监视器占用 → 关掉再上传 |

## 七、数据格式（重要）

### 7.1 CSV 实时副本：**宽表，一行一轮**

```csv
iso_time,round_id,v1,i1,v2,i2,v3,i3,v4,i4
2026-10-12 15:56:25,1,-7.17045e-05,6.56688e-12,-0.000529928,-8.68163e-12,-0.00138152,5.5831e-12,-0.000532182,2.69802e-11
2026-10-12 15:56:27,2,3.11824e-05,7.62438e-12,-4.82313e-05,7.67346e-11,-3.42538e-05,4.9773e-11,1.07207e-06,2.92067e-12
2026-10-12 15:56:29,3,-6.8232e-05,...
```

| 列 | 含义 | 说明 |
|---|---|---|
| **iso_time** | 本轮的**网格时刻** | **只到秒**；**严格按采样间隔递增**（设 2 s 就每行差 2 s，设 5 s 就差 5 s）。它是 `t0 + n × 间隔` 算出来的，所以永不断档、永不等间隔失真 |
| **round_id** | 轮号 | 在**同一天内连续递增**，程序重启也不会重置 → 重启后的数据仍能按它排序 |
| **v1,i1,v2,i2,v3,i3,v4,i4** | 4 路的电压/电流 | 某路读失败 → 该格**留空**（不写 0，避免误判）；整轮失败 → 写一行空数据，**保证时间列不断档** |

> 💡 **时间列的两种含义**（都在 SQLite 里，溯源时可查）：
> - `iso_time`（CSV 里这一列）= **本轮网格时刻**，代表"这一轮是什么时候测的"，等间隔
> - `samples.ts`（只在数据库里）= 每个测量点的**物理精确时刻**，8 个点相差约 190 ms
>
> 你的器件在 7 天尺度上变化很慢，用网格时刻画图完全够，而且横轴天然均匀。

### 7.2 数据库里另外两列的含义（CSV 里没有，供追溯）

| 列 | 含义 | 用途 |
|---|---|---|
| **run_id** | 第几次"运行会话"——每启动一次 `main.py` 就是一个 run（1,2,3…） | 区分"这批数据是哪次连续采集的"；`runs` 表里还存了每 run 的**起止时间**和**当时的完整配置**（`config_json`），半年后能回答"当时参数是多少" |
| **quality** | 数据质量：`0`正常 / `1`可疑 / `2`无效 | 目前读数失败会记 `2`；后处理可 `WHERE quality=0` 一次滤掉坏点 |

### 7.3 存储结构

```
D:\IV_data\
└─ 2026-10-12\
   ├─ 2026-10-12.db              主存储（SQLite，WAL）
   │     samples    每个测量点一行（含精确 ts、grid_ts、run_id、quality）
   │     round_log  每轮一行（含空轮）→ 宽表可完整重建
   │     runs       每次运行的起止时间与配置快照
   │     events     事件日志（断线、重连、网格重对齐等）
   │     agg_1min / agg_1hour   多分辨率聚合表（画 1 天 / 7 天视图用）
   └─ 2026-10-12_samples.csv     实时副本（宽表，一行一轮）
```

- **命名零填充**（`2026-10-03` 而不是 `2026-10-3`）→ 按文件名排序 = 按时间排序 ✓
- **WAL 模式** → 断电不损坏，最多丢 1~2 秒
- **7 天数据量**：约 30 万行 / **~15 MB**（2 s 间隔、含温湿度；比长表省很多）
- **画图不卡**：多分辨率聚合表 + 按像素降采样 → 绘图耗时只跟屏幕宽度有关，与数据量无关

> ⚠️ **格式变过一次**：如果你的目录里有早期版本生成的 CSV（长表、毫秒时间戳），
> 建议删掉那个文件重跑 —— 新旧格式混在一个文件里会乱。
> 数据库会自动迁移（补 `grid_ts` 列），不用管。
> 第一次git修改尝试ing
