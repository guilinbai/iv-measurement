### 两台万用表（USB）

| 用途 | VISA 地址 | 序列号 | 固件 | 当前功能 |
|---|---|---|---|---|
| **测电压** | `USB0::0x05E6::0x6500::04587682::INSTR` | 04587682 | 1.7.12b | `VOLT:DC` |
| **测电流** | `USB0::0x05E6::0x6500::04468141::INSTR` | 04468141 | 1.0.04b | `CURR:DC` |

两台都在 **NPLC=1、自动调零开、电压量程 0.1 V、电流量程 10 µA** —— 正好适合小信号器件。

### 关键实测数据（决定时序参数）

| 指标 | 实测值 | 影响 |
|---|---|---|
| `:READ?` 耗时 | **约 21~25 ms**（自动量程下） | 但**自动调零每 5 次会到 43 ms**，自动量程切换时更慢 → 固件 `T_WINDOW=80 ms` 才安全 |
| 电压档本底噪声 | ±0.1 mV 波动 | 远优于 mV 级信号 ✓ |
| **电流档本底** | **±20~50 pA** | 比 10 µA 信号低 5 个数量级 ✓ 系统很干净 |
| 一轮 8 次测量 | **实测 1.80 s**（T_WINDOW=80） | 间隔 2 s 余量 **0.20 s（偏紧）**；建议 2.5 s |

### 串口

| 端口 | 设备 | 说明 |
|---|---|---|
| **COM9** | USB-SERIAL CH340 | **Arduino（开关阵列）** ✓ |
| COM11 | USB-SERIAL CH340 | 另一个 CH340 设备（不是 Arduino） |
| COM5 / COM6 | 蓝牙串口 | **不要探测**（Windows 打开会卡住，脚本已自动跳过） |
| COM1 | 主板串口 | 同上 |

> ⚠️ **CH340 没有序列号**，USB 重新插拔后端口号会反复变（实测见过 `COM7/COM9` → `COM9/COM11` → `COM12/COM13`）。
> **所以脚本里不要写死端口号**：程序会自动探测；烧录固件前也要先探测（见下方"端口总在变怎么办"）。
> 所以 `config.yaml` 里 `arduino.port` **建议留空**，由程序**自动探测**（发 PING，谁回应谁是 Arduino）。

## 五、config.yaml 怎么改

| 想要什么 | 改哪里 |
|---|---|
| 换数据存放位置 | `storage.dir` |
| 改采样间隔 | `acquisition.interval_s`（**最小 2.16 s** 比较稳；2.0 s 也行但余量只有 0.20 s） |
| 关闭"边测边写 CSV" | `storage.write_csv_realtime: false`（不推荐，会失去断电保护） |
| 手动指定 Arduino 端口 | `devices.arduino.port: ""`（**建议留空自动探测**，见下方"端口总在变"） |
| 调整读数精度/速度 | `devices.dmm_*.nplc`（小信号建议保持 1） |
| **量程策略** | `devices.dmm_*.autorange`（**默认 true = 自动量程**，见下方） |

### ⚠️ 量程策略（重要：不要锁死量程）

| 配置 | 行为 | 什么时候用 |
|---|---|---|
| **`autorange: true`（默认）** | 表自己选档位 | ✅ **正常用这个** |
| `autorange: false` + `range: 0.1` | 锁死在 100 mV 档 | ⚠️ **只有确认被测值一定在该档内**才用 |

**为什么不能锁死**：把电压表锁在 0.1 V 档后，一旦器件 Voc 超过 0.1 V（比如 1.5 V）就**超量程报错**，读数无效。电流表锁在 10 µA 档同理。

**自动量程的两个实测特性**（我已验证并据此调整参数）：

| 特性 | 实测 | 应对 |
|---|---|---|
| 信号稳定时**不切换档位** | 每次读数仍只要 21~25 ms | 无需额外代价 ✓ |
| **自动调零（AZER）每 5 次**多花约 20 ms | 周期性出现 41~43 ms | 固件 `T_WINDOW` 从 50 → **80 ms** |
| 量程切换时那一次较慢 | 可能 60~100 ms | **启动时预热 3 次**让档位先稳定（程序已自动做） |

日志里会显示实际量程，例如：
```
电压表: 已配置 func=VOLT:DC 量程=0.1(自动)
电压表: 预热 3 次，量程=0.1(自动)，单次 21~23 ms
```

### ⚠️ 间隔保护（程序会提示）

| 采样间隔 | 一轮 1.80 s 之后的余量 |
|---|---|
| **2.5 s（推荐）** | 0.70 s ✓ 舒服 |
| 2.0 s（你当前的设定） | **0.20 s** ⚠️ 可行但偏紧 |
| 1.8 s | ~0 s ✗ 临界 |
| < 1.8 s | 负 ✗ 跑不完 |
| **最小建议** | **2.16 s**（= 1.80 × 1.2） |

**想用 2.0 s 又想要更多余量**：把 `config.yaml` 的 `t_settle_ms` 从 80 降到 60（同时固件里 `T_SETTLE` 也要改并重新上传），一轮就降到 1.64 s，余量变 0.36 s。

程序会在间隔过小时红字警告（命令行/界面都会）。

## 六、常见问题

| 现象 | 原因 / 解决 |
|---|---|
| `[X] 打开 VISA 失败` | NI-VISA 没装，或万用表被其它软件占用（KickStart 等） |
| 只找到 1 台表 | 检查另一台 USB 是否插好；两台表的 USB 线别插在同一个 Hub 上尝试换口 |
| 串口无回应 | ① Arduino 被 IDE 的串口监视器占用 → 关掉；② 数据线是"只能充电"的线；③ 板子没插好 |
| 脚本输出中文乱码 | 用 **Windows Terminal** 或 **VS Code** 的终端运行；或在 cmd 里先执行 `chcp 65001` |
| 探测串口卡住很久 | 已修复：脚本现在**只探测 USB 串口芯片**，自动跳过蓝牙/主板串口 |
| **端口号又变了（如 COM9 → COM12）** | USB 重新枚举，CH340 端口号会变。**程序会自动探测，不用管**；但烧录固件时要先探测（见下） |

## 八、第 3 期新增：温度采集与电压源控制

### 8.1 温度采集器（TA612，COM4）

**协议**（来自《TA系列通讯协议.docx》，已用真机 TA612 V3.50 验证）：

| 项 | 内容 |
|---|---|
| 串口 | 9600, 8N1 |
| 取型号/版本 | 发 `AA 55 00 03 02` → 回 `55 AA 00 07 64 02 5E 01 CB`（型号 0x0264=TA612，版本 V3.50） |
| 取实时温度 | 发 `AA 55 01 03 03` → 回 `55 AA 01 0B | ch1 | ch2 | ch3 | ch4 | Sum` |
| 数据换算 | 16bit 低字节在前，**温度 = 原始值 / 10**（℃） |
| 校验 | 从帧头起累加取低 8 位 |

实测：ch1 = ch2 = 26.7 ℃，**ch3/ch4 返回 28000**（未接探头的标志值，程序已自动过滤为 None）。
采集节奏独立于测量（`devices.tasensor.interval_s`，默认 5 秒）。

### 8.2 电压源（Wanptek，COM13，MODBUS-RTU）

**协议**（来自《通讯协议4_1.pdf》）：8N1、**波特率 2400**、**从站地址 0**（都是出厂默认）、数据小端、CRC16-MODBUS。

| 操作 | MODBUS 指令 | 地址 |
|---|---|---|
| 读状态/电压/电流 | `0x03` 读寄存器 | 0x0000 状态0, 0x0001 状态1, 0x0002 当前电压, 0x0003 当前电流, 0x0004 设置电压, 0x0005 设置电流, 0x0006 最大电压, 0x0007 最大电流 |
| 设电压 | `0x10` 写寄存器 | **0x0001**（值 = 电压 × 100） |
| 设限流 | `0x10` 写寄存器 | **0x0002**（值 = 电流 × 1000） |
| 输出开关 | `0x05` 写线圈 | **0x0000**（0xFF00=开 / 0x0000=关） |

实测本机电源：**31 V / 5.2 A**，初值 设定 10.690 V / 1.000 A、输出已开。

> ⚠️ **之前探测失败的原因**：我一直试 9600 bps + 地址 1，而设备默认是 **2400 bps + 地址 0**。
> 如果换电源，用 `python -m ivcore.powersupply COM13` 只读自测（不会改任何设置）。

**安全设计**：
- 超过设备最大电压（31 V）直接拒绝
- 退出程序**默认不关输出**（`off_on_exit: false`），避免打断控温实验
- 界面操作：`驱动电压源：[10.69] V  [应用]  [输出：开/关]  实测 0.000V/0.000A 设定 10.69V/1.000A 恒压`

### 8.3 界面：三个图共享时间轴

`
┌ 电压 Voc   4 条曲线 ┐
├ 电流 Isc   4 条曲线 ┤ ← X 轴联动（缩放/平移任一个，其余同步）
├ 温度 ℃     T1、T2   ┘   ch1 红 / ch2 蓝；两条线的**间距就是 ΔT**
`
状态栏还会直接显示 `T1=26.7  T2=26.7  ΔT=0.0 ℃`。
**温差会随驱动电压增大而拉大** —— 图上看两条线的间距即可。

### 8.4 数据文件新增

同一天目录下多一个 **`YYYY-MM-DD_env.csv`**（一行一次温度采样）：

`csv
iso_time,t1,t2,dt
2026-10-21 16:54:08,26.70,26.70,0.00
2026-10-21 16:54:13,26.80,26.60,0.20
`
- `t1`/`t2` = ch1/ch2 温度（℃）
- `dt` = **温差**（自动计算）
- 对应数据库表 `env(ts, run_id, sensor, ch, value, unit, quality)`
- 时间戳用 PC 时间（设备帧里没有时间戳），所以与测量数据天然共轴 ✅

## 七、数据格式（重要）

### 7.1 CSV 实时副本：**宽表，一行一轮**

```csv
iso_time,round_id,v1,i1,v2,i2,v3,i3,v4,i4
2026-10-12 15:56:25,1,-7.17045e-05,6.56688e-12,-0.000529928,-8.68163e-12,-0.00138152,5.5831e-12,-0.000532182,2.69802e-11
2026-10-12 15:56:27,2,3.11824e-05,7.62438e-12,-4.82313e-05,7.67346e-11,-3.42538e-05,4.9773e-11,1.07207e-06,2.92067e-12
2026-10-12 15:56:29,3,-6.8232e-05,...
```

| 列 | 含义 | 说明 |
|---|---|---|
| **iso_time** | 本轮的**网格时刻** | **只到秒**；**严格按采样间隔递增**（设 2 s 就每行差 2 s，设 5 s 就差 5 s）。它是 `t0 + n × 间隔` 算出来的，所以永不断档、永不等间隔失真 |
| **round_id** | 轮号 | 在**同一天内连续递增**，程序重启也不会重置 → 重启后的数据仍能按它排序 |
| **v1,i1,v2,i2,v3,i3,v4,i4** | 4 路的电压/电流 | 某路读失败 → 该格**留空**（不写 0，避免误判）；整轮失败 → 写一行空数据，**保证时间列不断档** |

> 💡 **时间列的两种含义**（都在 SQLite 里，溯源时可查）：
> - `iso_time`（CSV 里这一列）= **本轮网格时刻**，代表"这一轮是什么时候测的"，等间隔
> - `samples.ts`（只在数据库里）= 每个测量点的**物理精确时刻**，8 个点相差约 190 ms
>
> 你的器件在 7 天尺度上变化很慢，用网格时刻画图完全够，而且横轴天然均匀。

### 7.2 数据库里另外两列的含义（CSV 里没有，供追溯）

| 列 | 含义 | 用途 |
|---|---|---|
| **run_id** | 第几次"运行会话"——每启动一次 `main.py` 就是一个 run（1,2,3…） | 区分"这批数据是哪次连续采集的"；`runs` 表里还存了每 run 的**起止时间**和**当时的完整配置**（`config_json`），半年后能回答"当时参数是多少" |
| **quality** | 数据质量：`0`正常 / `1`可疑 / `2`无效 | 目前读数失败会记 `2`；后处理可 `WHERE quality=0` 一次滤掉坏点 |

### 7.3 存储结构

```
D:\IV_data\
└─ 2026-10-12\
   ├─ 2026-10-12.db              主存储（SQLite，WAL）
   │     samples    每个测量点一行（含精确 ts、grid_ts、run_id、quality）
   │     round_log  每轮一行（含空轮）→ 宽表可完整重建
   │     runs       每次运行的起止时间与配置快照
   │     events     事件日志（断线、重连、网格重对齐等）
   │     agg_1min / agg_1hour   多分辨率聚合表（画 1 天 / 7 天视图用）
   └─ 2026-10-12_samples.csv     实时副本（宽表，一行一轮）
```

- **命名零填充**（`2026-10-03` 而不是 `2026-10-3`）→ 按文件名排序 = 按时间排序 ✓
- **WAL 模式** → 断电不损坏，最多丢 1~2 秒
- **7 天数据量**：约 30 万行 / **~15 MB**（2 s 间隔、含温湿度；比长表省很多）
- **画图不卡**：多分辨率聚合表 + 按像素降采样 → 绘图耗时只跟屏幕宽度有关，与数据量无关

> ⚠️ **格式变过一次**：如果你的目录里有早期版本生成的 CSV（长表、毫秒时间戳），
> 建议删掉那个文件重跑 —— 新旧格式混在一个文件里会乱。
> 数据库会自动迁移（补 `grid_ts` 列），不用管。
> 第一次git修改尝试ing
