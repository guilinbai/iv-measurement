## 一、一句话总结这次重写的依据

我原来一直照协议文档推测行为，实测发现**设备只实现了一小部分功能**：

| 功能 | 协议说 | 实测 |
|---|---|---|
| 读寄存器 `0x03` | 可读 1~8 个 | **只有读 8 个有回应**，读 1/2/4 个全部超时（1.08 秒满额） |
| 写寄存器 `0x10` | 可写 1~3 个 | **只有写 3 个有回应**（约 110ms），写 1/2 个超时 |
| 写单个寄存器 `0x06` | 没提 | **不支持**，超时 |
| 读线圈 `0x01` | 支持（0x0004/0x0005） | **完全不支持**，8 个地址全部超时 |
| 写线圈 `0x05` | 支持（0x0000 输出） | **完全不支持**，`0xFF00`/`0x0001`/`0x0000` 全无应答 |
| 控制字端序 | 未明说 | **高字节先**（决定性实验，见下） |

**决定性实验（控制字端序）**：

```
控制字 0x0100 发字节 `01 00`（高字节先） → 状态0=0x1101 → PS(bit8)=1 → 输出打开 ✓
控制字 0x0100 发字节 `00 01`（小端）     → 状态0=0x0001 → PS=0    → 输出仍关 ✗
```

两条命令设备都正常应答（CRC-OK），但只有高字节先才生效。**这就是之前"点了输出开没反应"的根因之一。**

## 三、★ 关键代码段：`_write3()` 的 15 字节帧（L278~L325）

```python
body = [self.addr, 0x10,
        0x00, 0x00,                                    # 起始地址 0x0000
        0x00, WRITE_COUNT,                             # 个数 = 3   ← 必须是 3
        2 * WRITE_COUNT,                               # 字节数 = 6
        (ctrl >> 8) & 0xFF, ctrl & 0xFF,               # 控制字  ← 高字节先
        v_raw & 0xFF, (v_raw >> 8) & 0xFF,             # 电压    ← 小端
        i_raw & 0xFF, (i_raw >> 8) & 0xFF]             # 电流    ← 小端
```

逐字节：

| 字节 | 值 | 说明 |
|---|---|---|
| 0 | `00` | 从站地址 |
| 1 | `10` | 功能码：写多寄存器 |
| 2,3 | `00 00` | 起始地址 **0x0000**（地址字段固定先高后低） |
| 4,5 | `00 03` | 寄存器个数 **3** ← 实测写别的数量设备不理 |
| 6 | `06` | 字节数 = 3×2 |
| 7,8 | `ctrlH ctrlL` | **控制寄存器，高字节先** ← 发反了输出就开不了 |
| 9,10 | `vL vH` | 设定电压，**小端** |
| 11,12 | `iL iH` | 设定电流，**小端** |
| 13,14 | `crcL crcH` | CRC |

设备应答固定 8 字节：`00 10 00 00 00 03 81 D9`

## 四、★ 关键代码段：`read_status()` 的解析（L192~L277）

```python
# 状态寄存器 0/1：高字节先
stat0 = (data[0] << 8) | data[1]
stat1 = (data[2] << 8) | data[3]

# 其余寄存器：小端
le = lambda i: data[i] | (data[i + 1] << 8)
volt_raw  = le(4)    # 寄存器2 当前电压
curr_raw  = le(6)    # 寄存器3 当前电流
vset_raw  = le(8)    # 寄存器4 设定电压
iset_raw  = le(10)   # 寄存器5 设定电流
vmax_raw  = le(12)   # 寄存器6 设备最大电压
imax_raw  = le(14)   # 寄存器7 设备最大电流
```

位定义（L240~L262）：

| 字段 | 计算 | 含义 |
|---|---|---|
| `out_on` | `(stat0 >> 8) & 1` | **PS 输出开关** |
| `ocp` | `(stat0 >> 9) & 1` | OS |
| `lock` | `(stat0 >> 10) & 1` | LS 面板锁 |
| `big_endian` | `(stat0 >> 11) & 1` | BL |
| `cv` | `not ((stat0 >> 12) & 1)` | **WS=0 表示恒压** |
| `alarm` | `(stat0 >> 13) & 1` | AS |
| `v_scale` | VPOD(bit4): 0→100，1→10 | 电压除数 |
| `i_scale` | IPOD(状态1 bit4): 0→1000，1→100 | 电流除数 |

## 五、★ 关键设计：`_write_merged()`（L326~L354）

```python
def _write_merged(self, out_on=None, volts=None, amps=None):
    if not self.read_status():        # ★ 每次写之前都重新读
        return False
    i = self.info
    out = i["out_on"] if out_on is None else bool(out_on)   # None = 保持
    ocp = i["ocp"]
    ctrl = ((1 if out else 0) << 8) | ((1 if ocp else 0) << 9)
    v_raw = int(round((i["vset"] if volts is None else volts) * i["v_scale"]))
    i_raw = int(round((i["iset"] if amps is None else amps) * i["i_scale"]))
    return self._write3(ctrl, v_raw, i_raw)
```

**为什么必须先读**：协议强制一次写 3 个，若拿本地缓存填另外两项，会覆盖面板改动（比如点"输出开"把电压改回旧值）。

## 六、本版**故意不做**的事

| 不做 | 原因 |
|---|---|
| **自动重连** | 重连会在写操作中途改变端口和状态缓存，导致"基于错误前提去写"。串口出错直接抛异常，由你点「重连」按钮显式重连 |
| **端口自动扫描** | 上一版有 `find_port()`，扫所有 USB 口。删掉：不确定性和耗时都比收益大 |
| **写线圈 `0x05`** | 实测完全不支持，代码里不再尝试 |
| **读线圈 `0x01`** | 实测完全不支持 |

## 十、★ 关键实测：读数延迟 2.2 秒（settle_s 为什么是 2.5）

这一节是理解「为什么点了输出开、界面却显示 0.00V」的关键。

### 实测方法

probe_power_lag.py：打开输出后，每 0.3 秒读一次状态，连续 8 秒。

### 实测结果

`
打开输出后连续观察（每 0.3 秒读一次）：

t=0.44s   PS=1   实测 0.00V    ← PS 位立即变 1
t=0.89s   PS=1   实测 0.00V    ← 电压还是 0
t=1.33s   PS=1   实测 2.31V    ← 才开始上升
t=1.78s   PS=1   实测 2.31V
t=2.22s   PS=1   实测 4.50V    ← 才稳定到设定值
t=2.67s~8.00s  PS=1   实测 4.50V  ✓
`

关闭输出也一样：PS 位立即变 0，但电压要约 2 秒才降到 0（中间会读到 1.4~3.5V 残余）。

### 结论

| 数据 | 刷新速度 |
|---|---|
| **PS 位**（状态寄存器0 bit8） | **立即**（0.4 秒内可读到） |
| **实测电压 / 实测电流** | **约 1.3 秒后开始变化，2.2 秒才稳定** |

### 这解释过的现象

| 现象 | 真正原因 |
|---|---|
| 点输出开后"没输出" | PS=1，但**实测电压还是 0.00V**（等待不足，读到旧值） |
| 电源是开、"显示却是关" | 读到的是**上一个状态**的电压值（错位一个操作） |
| 设定 500mA 显示 120mA | 负载变化后电流约 2 秒才稳定 |

### 因此代码里的处理

`python
# output() 里分两段校验：
time.sleep(0.4)                     # ① 先用 0.4 秒确认 PS 位（立即生效）
if self.info["out_on"] != on: ...

time.sleep(self.settle_s)           # ② 再等 settle_s，读稳定的实测值
self.read_status()
self.last_verify = {...}            # 供界面显示"实测 → X V"
`

settle_s 默认 **2.5 秒**（实测下限 2.2）。调小到 2.0 以下会出现读数错位的假象。

### 代价

每次开关输出/改电压会**多等 2.5 秒**（界面会短暂无响应）。
如果嫌慢，config.yaml 里 settle_s 最低建议 **2.2**，不建议低于 2.0。
